# Privacy Audit Brand System

Privacy Audit uses a **Privacy Lens / Redaction Signal** identity: a focused, technical visual system built around local inspection, explainable findings, and deliberate redaction.

The project should feel like a careful pre-publication review tool—not a surveillance product, generic cyber-security dashboard, or compliance platform.

## Identity concept

The visual story is:

**local text → inspection lens → sensitive signal → redacted output**

The core mark combines:

- a scanning lens for review;
- text lines for source files;
- redaction bars for protected context;
- violet/cyan signal colors for detection and local inspection.

The logo intentionally avoids locks, shields, fingerprints, and initials so the repository keeps a distinctive identity among other security-related projects.

## Why these colors

- **Night Ink** keeps the interface focused without defaulting to plain black.
- **Iris Violet** gives the project an analytical identity distinct from common green security branding.
- **Signal Cyan** communicates local scanning and machine-readable inspection.
- **Redaction Rose** marks sensitive findings and hidden excerpts without implying that every detection is a confirmed secret.

## Typography and composition

Repository artwork uses common system-safe sans-serif fonts so the SVG assets render reliably on GitHub.

- Product name: bold geometric sans-serif.
- Status labels: compact uppercase sans-serif.
- Commands and paths: monospace in Markdown.
- Arabic credit: isolated on a separate line for correct direction and readability.
- Layout: generous negative space, a single inspection scene, and restrained signal colors.

## Asset rules

1. Keep the logo square and preserve internal padding.
2. Do not stretch or skew the lens mark.
3. Keep Redaction Rose reserved for sensitive-result cues.
4. Do not turn the palette into a neon cyber aesthetic.
5. Do not present detections as confirmed personal data or confirmed leaked secrets.
6. Do not add compliance seals, privacy certifications, or claims the scanner cannot prove.
7. Keep current capabilities separate from roadmap ideas.

## Repository presentation principles

- Lead with the project purpose, not a threat-oriented slogan.
- Explain the local-only/read-only boundary early.
- Keep limitations prominent enough to prevent overconfidence.
- Treat example findings as synthetic or illustrative.
- Keep Arabic and English long-form documentation separate.
- Prefer a few precise diagrams and tables over decorative clutter.

## Distinctive character

Privacy Audit should look like a **pre-publication privacy inspection instrument**. Its identity is about examining text while revealing as little sensitive context as possible.

It is intentionally different from:

- OCR Desk's paper/editorial scanning identity;
- Backup Sentinel's vault/verification identity;
- generic security products built around shields, padlocks, or warning triangles.
